The actual obsession

Agentic systems that do work

I’m interested in the engineering layer after “call an LLM”: coordination, tools, permissions, state, routing, evaluation, observability, and recovery.

01 / ORCHESTRATION

Multi-agent execution

Planner, worker, checker, critic, and boss patterns where roles are separated on purpose. Agents communicate through explicit state and evidence instead of trusting each other’s summaries.

task graphsagent-to-agentdurable staterework loopshuman override
02 / TOOLS

Real tool use

Filesystem, shell, Git, APIs, search, tests, and structured actions behind permission boundaries—not agents role-playing that they changed something.

MCP-style toolssandboxingapprovals
03 / ROUTING

Model routing

Use the cheapest, fastest model that can reliably complete the next step, then escalate when evidence says it should.

local modelscloud modelscost-aware
04 / VERIFICATION

Trust is not a test strategy

Independent checking, test execution, diff inspection, acceptance criteria, retry budgets, and escalation. The goal is not more agent chatter; it is a higher probability that the artifact at the end actually works.

evalsindependent checkerfailure recoveryevidence-first
05 / MEMORY

Long-running work

Resumable sessions, checkpoints, compacted context, project memory, and progress state so agents can survive work that lasts longer than one prompt.

checkpointsresumecontext control
